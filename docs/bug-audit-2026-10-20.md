# Bug audit — 2026-10-20

Source baseline: `79a86085c27bcee9de1852ba2ec31e8ac9505197`, primary checkout on `main`.

Each of the 20 cases below was reproduced with a failing regression before its fix.
The regression cases are in `tests/bug-regressions.h`, executed by `edit_tests`.
Related edge cases are additional assertions, not additional bugs in the count.

| # | Reproduction and original failure | Corrected behavior |
| --- | --- | --- |
| 1 | Numeric entities with signs or whitespace, such as `&#x+41;`, were decoded as valid characters. | Only digits valid for the entity's radix are decoded. |
| 2 | Repeated heading titles all received the same fragment identifier. | Generated identifiers receive collision-safe numeric suffixes. |
| 3 | A heading inside a list included its rendered list marker in its identifier. | Identifiers use heading content without the structural prefix. |
| 4 | `<h2 id="custom">Title</h2>` discarded its explicit identifier. | Explicit heading identifiers survive parsing and export. |
| 5 | `<ol start="0">` and negative starting numbers silently began at one. | Signed starting numbers are retained. |
| 6 | `<li value="7">` ignored the item's number override. | The override sets that item and subsequent numbering. |
| 7 | Converting `## Title ##` to normal text left the closing hashes. | Optional closing heading markers are removed along with the opening markers. |
| 8 | Table commands modified table-shaped text inside fenced code. | Fenced code is excluded, including fences inside containers. |
| 9 | Editing a table at end of file added a newline that was absent from the source. | The original final-newline state is retained. |
| 10 | Enter after `>  > item` lost the nested quote marker. | Spaced nested quote prefixes are continued. |
| 11 | Enter after `-   [x] done` lost the task checkbox and spacing. | The next task retains spacing and begins unchecked. |
| 12 | Validation decoded escaped, literal entity-like filenames a second time. | Attribute segments are decoded according to the Markdown parser's segment types. |
| 13 | Export combined consecutive, separate Markdown tables into one HTML table. | Each Markdown header starts its own table; multiple HTML header rows remain together. |
| 14 | Export split a code block longer than the reader's layout chunk into multiple `<pre>` elements. | Pieces sharing one code-block identity are joined without losing text. |
| 15 | Ordinary HTML table cells lost their vertical alignment on export. | Export retains top, middle, or bottom alignment. |
| 16 | Export collapsed nested blockquotes to one level. | All quote levels are emitted. |
| 17 | Enter on an empty quoted list item removed the enclosing quote too. | Leaving the list preserves the quote prefix. |
| 18 | Table commands modified table-shaped text in indented code. | Four-space and tab-indented code is excluded. |
| 19 | Query-only local links such as `?download=1` were resolved to a directory during export and Save As. | They retain the source document filename and query. |
| 20 | Damaged UTF-8 with an explicit UTF-8 BOM was reinterpreted as ANSI. | The BOM determines decoding; malformed byte sequences become replacement characters. |

The native editing test also clicks a link to the second of two identical headings,
then verifies that lazy layout does not move navigation back to the first heading.

## Validation

- Release build and CTest: **9/9 suites passed**, including the new regression
  cases, native editor checks, and the production executable's instrumentation check.
  Run with `python scripts/test_desktop.py pwsh -NoProfile -File scripts/build.ps1`.
- CommonMark: **652/652 examples passed** using `python scripts/commonmark.py`.
- Native editing: `python scripts/test-editing.py` passed, including duplicate-heading
  navigation, source/preview synchronization, both themes, Save As, conflicts, and recovery.
- Startup and search: `python scripts/test-startup.py` and
  `python scripts/test-search.py` passed. First-match painting took **9.20 ms**,
  before background counting began; next-match painting took **7.11 ms**.
- Formatting and whitespace: `scripts/format.ps1 -Check` and `git diff --check` passed.
- Two-run local benchmark (`scripts/benchmark.py --runs 2 --sizes 1024 1048576 10485760`):

| Document size | Median load/parse/check time | Median first content |
| --- | ---: | ---: |
| 1 KiB | 0.31 ms | 73.71 ms |
| 1 MiB | 51.45 ms | 90.08 ms |
| 10 MiB | 522.79 ms | 570.91 ms |

The benchmark also completed its long-paragraph, long-code, and long-table cases.
These are final-build measurements, not a controlled before/after performance comparison.
GUI checks ran on private Windows desktops; they do not establish physical-display behavior.

Detailed local logs are under `build/bug-audit-*.log`; benchmark data is in
`build/bench/bug-audit-2026-10-20.json`. This audit does not include a release or publication.
